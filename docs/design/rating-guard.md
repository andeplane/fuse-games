# Rating settlement limits

Round ratings use transactional, per-game UTC-day budgets stored with each account's standing. Each pair can play 200 rated rounds and exchange at most 400 absolute Elo points per day; each account can move at most 1,000 absolute points per day across all opponents. Opposite-direction exchanges both consume the budget. These preliminary ceilings allow 200 rounds with one opponent (over six hours at two minutes per round) before the round limit, though the Elo limit may bind earlier. Shorter games can reach the limit during an unusually long session. At midnight UTC budgets reset; this is not a rolling 24-hour window. Server clock rollback does not reset them.

Pairwise changes are weighted by the lower of the two accounts' confidence: 25% initially, increasing to 100% after 20 corroborated multiplayer settlements. Existing accounts start with zero confidence because older rating counters include solo rounds. Solo play cannot grow confidence. The server stores the counters and updates them with the ratings in the same transaction. Missing guard data starts fresh; malformed guard data fails closed. When an account reaches 600 distinct opponents in a day, additional pairs get no exchange that day, keeping the document bounded.

These measures make concentrated rating transfer slower; they do not verify identity or prove that a game was played. Self-controlled accounts can corroborate one another, grow confidence, rotate opponents and spread activity over UTC days. The receipt currently has no server-verified round start or duration; minimum-duration checks remain outstanding. Thresholds are provisional and require observation of actual play distributions before competitive launch.

An operator with read access to the named Firestore database can run `ROOM_COLLECTION_PREFIX=... GOOGLE_CLOUD_PROJECT=... FIRESTORE_DATABASE_ID=... pnpm exec tsx scripts/rating-anomalies.ts fuse-riders 10000`. It reads at most the requested number of standings (plus one to signal truncation), writes nothing, and emits a private JSON report of current UTC-day absolute rating movement, repeated pairs, each account's opponent set, and connected components apart from the largest. IDs are deterministic pseudonyms, not anonymous data: restrict the output and credentials to authorized operators. Set an appropriate read limit; `truncated: true` means the report cannot represent the full ladder. The graph describes only accounts with activity in the current UTC day, not lifetime opponents; old daily counters are overwritten. Disconnected groups and high movement are leads for review, not proof of abuse.
