# Fusero source parity

The user requires a close gameplay clone of Liero/OpenLieroX, with Fuse graphics and Fuse's existing networking and room recovery. The earlier original prototype is not the acceptance baseline. Readiness requires source-derived mechanics and verification; human gameplay acceptance remains separate.

## Baseline

OpenLieroX release `20260717.2`, source commit `0a20c6d0a10ed63b28a15f05c771913c294efbf6`, classic LX56 simulation and the packaged `share/gamedir/Classic/script.lgs` (internally Liero v1.0, format v7). Source and data overrides take precedence over generic fallback defaults. The decompiler's example mod is not equivalent to the packaged mod.

Fusero now selects native **JailBreak (1200×600)** by default, following the user's explicit larger-map playtest feedback. Its native material plane has open routes and destructible dirt. **Castle Strike (1350×550)**, **Factory (1200×480)** and **Dirt Level (504×350)** are also selectable in Game settings. Dirt is the upstream fresh-configuration startup map; selecting JailBreak is a room-content choice, not a claim that upstream's default changed. Each level retains its original physical material plane.

## Architecture

Keep Fuse rooms, peer transport, input-log rollback, validated checkpoints and peer recovery. Port gameplay rules and immutable mod data from the pinned source into pure modules with explicit clocks, inputs, terrain and seeded evolving decision state. Native reference fixtures compare trajectories and effects with source behavior. Do not embed a disconnected web demo or replace Fuse's room model with the original host-dependent protocol.

Every authoritative state element—including per-projectile random indices, rope flight and attachment, weapon charge, timers, pixel terrain, score, respawn, input timestamps, pending shots and client physics phase—participates in checkpoints and replay. Rendering reads this state and cannot change mechanics. Personal follow cameras/minimaps and shared-TV overview remain presentation.

The deterministic compatibility profile is the native local/listen path at 100 FPS: each outer frame delivers the previous frame's captured shots, executes due 11 ms client physics iterations, then the server phase. Fuse runs five outer frames per 50 ms input-log tick. Input uses elapsed outer time; projectiles retain their own integer millisecond clocks. Server match time is one outer frame ahead of the simulation timestamp, matching native `serverFrame`. Wall-clock respawn and bonus timestamps are mapped to the deterministic outer clock. Native network delay and arbitrary render frame timing are deliberately replaced by this fixed profile.

## Current status

The source catalog and retained native levels regenerate from digest-checked files. Source-extracted C++ fixtures exercise movement, aim, rope, projectile initialization, contact/action behavior and sustained Laser timing. Exact physical masks, recorder ring quirks, selected-slot timers, scoring, strict respawn gates and optional bonuses have focused regressions. Integration checks cover full state recovery and late/reordered inputs; browser verification is recorded separately in the pull request.

The user rejected the preceding visual scale and controls as unplayable. The old 320×180 desktop / 192×144 phone crop, enlarged worm/gun art and WASD/F/R control mapping were incorrect. Earlier mechanics tests and convergence checks did not validate visual scale or gameplay feel. The repair retains native display/world conversion: two logical pixels per world pixel; maximum worm/gun envelope 10×9 world pixels; pixel projectile 1×1; crosshair 3×3 at a distance of 16 world pixels. Network view dimensions remain independent of display aspect, while local views follow the native aspect computation.

Exact Original PC and Original Mac keyboard presets are available. Original PC is the browser default to match the official WebAssembly reference on every platform; Original Mac can be selected under MENU → GAME CONTROLS → Keyboard preset. That local preference does not change authoritative room state or physics.

The official WebAssembly release has been played through its UI with native PC fire, dig, aim and rope inputs. The active interaction visibly produced explosions, health changing from 100 to 84 and charge changing from 100 to 66. These observations establish actual reference interaction, not whole-session equivalence. The repair's targeted game run passes 164 tests, and its browser smoke covers native controls, zoom, multiplayer and recovery. This is bounded evidence, not user acceptance or proof of whole-match equivalence.

Remaining qualification limits: the fixtures are extracted kernels and a specified local timing session, not a whole-native-match equivalence proof. Fuse bots choose ordinary inputs with a Fuse policy; native AI is not ported. Seeded authoritative randomness replaces native C `rand`. Pinned software trigonometry guarantees deterministic browser replay, but rounding its double result to float32 can differ from a native platform's `sinf` by one ULP (verified at 13 degrees). Human comparison of movement, weapons and rope feel is still required. No production publication or full parity acceptance is claimed.
